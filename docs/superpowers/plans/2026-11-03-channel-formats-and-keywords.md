# Channel Formats and Keywords Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each channel's bible holds formats (keywords, length, pace, intent,
shot hold, title template, intro) and pillar keywords, and research, script,
visuals and publish read them as channel-agnostic slots.

**Architecture:** New pure modules in `packages/schemas` (`formats.ts`,
`channel-publish.ts`, `cohesion.ts`) hold every rule; the bible schema gains
the fields and upgrades old versions on read; `packages/db` resolves a
project's format beside its frozen bible; prompts and runners take the format
as input. An empty slot composes exactly today's prompt.

**Tech Stack:** TypeScript strict, Zod 4, Drizzle (Postgres), Inngest, Next.js
App Router server actions, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-channel-formats-and-keywords-design.md`

## Global Constraints

- The code is the playbook; the bible is the channel. No channel name, keyword or number in code or a prompt template.
- An empty slot composes today's prompt. The lift fixtures (`packages/providers/src/prompts/lift/__fixtures__`) are never regenerated by this work; they are the snapshot test.
- Every new check warns; none refuses a save, a start or a publish.
- Mock providers by default (`MOCK_PROVIDERS=1`); no real VidIQ, model or render call unless the owner asks in that moment.
- VidIQ credits shown before spending and checked against the monthly cap (`checkVidiqBudget`, `spendVidiq`).
- Anything an Inngest run reads that this work adds is read inside a `step.run`; a run parked before a deploy must not crash on a missing field.
- `'use server'` files export only async functions.
- Format runtime limits: `3 ≤ min ≤ default ≤ max ≤ 240`; the start limit is 60 until Task 20.
- `wordsPerMinute` 80 to 200, default 150. `shotHold` 1 to 4 in steps of 0.5, default 1.
- Up to 6 formats; up to 6 keywords per format and per pillar, 60 characters each.
- Channel tags may use at most 150 of the 500 tag characters. `HASHTAGS_MAX` stays 3.
- `channelHashtag`: letters and digits only, up to 30, stored without `#`. `channelFooter`: up to 1,000 characters.
- Staleness of VidIQ data: `SEARCH_BRIEF_STALE_DAYS` (30). Nothing is cleared.
- Shorts are unchanged.
- PROGRESS.md: one section for this work with a checklist per phase; decision numbers taken after `git fetch` of origin/master at merge.
- Verification per package, never one whole `pnpm test` (600 s watchdog). Every Bash call that runs tests uses `timeout: 600000`.
- Before each commit: `git ls-files -z -- . ':!docs' | xargs -0 -n 80 pnpm exec prettier --check --ignore-unknown`, `pnpm lint`, `pnpm typecheck`.
- Database tests need Docker Desktop running and `pnpm db:migrate:test` first. Never run two database suites at once.
- Migrations: generate with `pnpm db:generate`; before merging, compare `packages/db/drizzle/meta/_journal.json` with origin/master and regenerate as the next number if another branch took it.

## Review Focus

1. **Old stored bibles.** Boom & Busters' v1, Real Power Pyschology's blank v1 and its draft (a copy of Boom & Busters) must read, save, draft and copy with no error and with the upgrade's values. Pinned in Task 2 (`upgradeStoredBible` cases) and Task 3 (stored-row round trip).
2. **A format key that no longer exists.** A case or project pointing at a format removed from a later bible resolves to the primary format everywhere (research seed, start control, runners). Pinned in Task 1 (`resolveFormat` unknown key) and Task 10 (case with a stale key).
3. **Template slots with no value.** A template using `{formatKeyword}` or `{pillar}` when the value is empty never leaks a literal `{…}` into a prompt or title, and an unfillable required slot is not reported missing. Pinned in Task 6.
4. **Tag overflow and case duplicates.** Kept tags, channel tags, format and pillar keywords and brief tags differing only in case are deduplicated, the owner's kept tags survive first, and the total stays within 500 characters. Pinned in Task 8.
5. **Hashtag input typed with `#`, spaces or a trailing comma** is refused by the schema with a plain message in the form, never stored half-clean. Pinned in Task 2 and Task 5.
